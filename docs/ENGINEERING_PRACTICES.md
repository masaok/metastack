# Engineering practices

This repository follows [Engineering practices that survive the stack](https://www.expeditionlabs.co/resources/engineering-practices) by Expedition Labs: 31 techniques in 7 themes, stated as rules. This document is the audit of this codebase against them. It records what was adopted, how, and what was deliberately not adopted and why, so the same suggestion does not come back in six months (technique 6.4).

Last audited: 2026-10-02. Status column: **done**, **setting** (a repository setting a human applies, not a file), **n/a** (the condition the technique addresses does not exist here), **deferred** (with the condition that would flip it).

## 1. Verification has to be structural, not voluntary

| #   | Technique                              | Status  | How it is done here                                                                                                                                                                                                                                                                                                                                                       |
| --- | -------------------------------------- | ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1.1 | Hosted CI, not just local hooks        | done    | `.github/workflows/ci.yml`: ten named jobs (`typecheck`, `lint`, `format`, `test`, `build`, `e2e`, `docs`, `blog`, `guardrails`, `gitleaks`). `permissions: contents: read`, per-ref concurrency with cancel-in-progress, every third-party step pinned to a commit hash with the version in a comment, `pnpm install --frozen-lockfile`.                                 |
| 1.2 | Staged-files-only pre-commit hook      | done    | `simple-git-hooks` installs the hooks from the root `prepare` script. Pre-commit runs `lint-staged`, which runs Prettier in write mode on staged paths only and re-stages them (about one second). Typecheck and build run at pre-push, not pre-commit.                                                                                                                   |
| 1.3 | Read-only lint in every automated path | done    | `lint` is `eslint` with no `--fix`; `lint:fix` exists for humans only. `format:check` is wired into CI; `format` (write mode) is never run by a hook except on staged files, where the result is re-staged so the committed snapshot is the one that passed.                                                                                                              |
| 1.4 | Required status checks on main         | setting | Branch protection on `main` requires the nine job names above, with "require branches to be up to date". Applied via the GitHub API on 2026-10-02. Administrators are not blocked from direct pushes (see rejected items); the pre-push hook is the gate for that path.                                                                                                   |
| 1.5 | Host-faithful build before deploy      | done    | The `build` job runs `pnpm build` on the Node major from `.nvmrc`, which is the same major the host project is set to. The pre-push hook also runs the production build as the fallback gate for direct pushes to `main`. The host's root directory and Node version are documented alongside the deploy notes, because the first deploy failed on exactly that mismatch. |

## 2. Encode the rule in the compiler, not in a document

| #   | Technique                                | Status | How it is done here                                                                                                                                                                                                                                                                                                                                                                                                     |
| --- | ---------------------------------------- | ------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 2.1 | Compiler-enforced client/server boundary | n/a    | The app is fully static and has no server-side modules, credentials or database connections. There is nothing to mark `server-only`. Condition that flips it: the first module that reads a secret or opens a connection. When that happens, `server-only` becomes a declared dependency and the first import of that module, and `AGENTS.md` already says so.                                                          |
| 2.2 | Every committed config has its tool      | done   | Prettier config → `prettier` dependency → `format` job. ESLint configs → `eslint` → `lint` job. Vitest configs → `vitest` → `test` job. Playwright config → `@playwright/test` → `e2e` job. Import ordering (`@ianvs/prettier-plugin-sort-imports`) and class ordering (`prettier-plugin-tailwindcss`) are installed and enforced. The one-off reformat landed as its own commit, recorded in `.git-blame-ignore-revs`. |
| 2.3 | Guides describe the code that exists     | done   | `CONTRIBUTING.md` (human process), `AGENTS.md` (agent guardrails), `.github/pull_request_template.md` (one line). Each names the actual data layer (Dexie), test runner (Vitest, Playwright) and layout. The original plan mentioned shadcn/ui and Velite; neither is a dependency and neither is mentioned as a target.                                                                                                |

## 3. Every version and constant gets exactly one home

| #   | Technique                                 | Status | How it is done here                                                                                                                                                                                                                                                                                                                                             |
| --- | ----------------------------------------- | ------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 3.1 | One declared runtime version              | done   | `.nvmrc` = 22, `engines.node` = `^22`, `@types/node` = 22.x, CI reads `.nvmrc`. Dependabot is told not to bump `@types/node` across a major. Before this audit `engines` said `>=20.9`; that was the drift.                                                                                                                                                     |
| 3.2 | One shared setup step reading versions    | done   | `.github/actions/setup/action.yml`: pnpm version from `packageManager` in `package.json`, Node from `.nvmrc`, frozen-lockfile install, pnpm cache keyed on the lockfile. Every job calls it. Playwright's browser install runs `--with-deps` so a cache hit still installs system libraries.                                                                    |
| 3.3 | Derived categorizations from one constant | done   | `packages/content/src/schema.ts` exports `TAGS`, `DECK_SLUGS`, `CARD_TYPES` as `const` arrays; the zod enums, the TypeScript unions, the card browser's filter chips and the deck pages are all derived from them. Rubric thresholds live once in `ratingFromRubric`; prose that quotes them (homepage, ADR 0002) is prose, and the unit tests pin the numbers. |
| 3.4 | Dependency automation respecting pins     | done   | `.github/dependabot.yml`: weekly grouped minors and patches, majors as separate PRs, `@types/node` major ignored, GitHub Actions grouped weekly so the hash pins move forward.                                                                                                                                                                                  |

## 4. Make checks deterministic, and prove they can fail

| #   | Technique                                    | Status | How it is done here                                                                                                                                                                                                                                                                                                                                                                 |
| --- | -------------------------------------------- | ------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 4.1 | Code generation inside the typecheck command | done   | `generated/cards.json` is produced by `compile`. Every `typecheck` and `test` script that reads it runs the compiler first (root and per package), so a clean checkout and a warm tree give the same answer.                                                                                                                                                                        |
| 4.2 | Proof-of-failure test for every custom check | done   | `scripts/check-public.test.sh` builds throwaway repositories and asserts the guardrail fails on each condition it detects, including an untracked file. `scripts/check-docs-links.test.mjs` does the same for the link checker. The content validator's negative fixtures are in `packages/content/test/compile.test.ts`. CI runs each test immediately before the check it proves. |
| 4.3 | Import smoke test over real entry points     | done   | The only non-app entry points are `scripts/compile.ts` and `scripts/validate.ts`, started with `tsx` exactly as CI and the build start them (`pnpm validate`, `pnpm build`). There is no test-runner stub on that path. If a daemon or CLI is added, this row becomes a script.                                                                                                     |
| 4.4 | Fail-safe changed-files gate                 | n/a    | No job skips on changed files; everything runs every time. Total CI time is a few minutes. Condition that flips it: CI time becoming a bottleneck, at which point the skip must default to "run everything".                                                                                                                                                                        |
| 4.5 | Job-level skip, never workflow path filters  | done   | The workflow has no `paths` filter, so every required check always reports.                                                                                                                                                                                                                                                                                                         |

## 5. Durable state needs a version history

| #   | Technique                                 | Status | How it is done here                                                                                                                                                                                                                                                                                                                 |
| --- | ----------------------------------------- | ------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 5.1 | Numbered migrations                       | done   | The only durable store is the user's IndexedDB. Dexie schemas are versioned: `db.version(1).stores(...)` is the baseline and is never edited; a schema change is a new `version(n+1)` with an `upgrade` function. The export envelope carries `version: 1` and import rejects unknown versions. Rule recorded in `ARCHITECTURE.md`. |
| 5.2 | Language-neutral migration format         | n/a    | One runtime (TypeScript in the browser) owns the store.                                                                                                                                                                                                                                                                             |
| 5.3 | Harvest the accidental migration log      | n/a    | No create-if-not-exists block exists to harvest.                                                                                                                                                                                                                                                                                    |
| 5.4 | Retire the replaced mechanism             | done   | Applied as a rule for this repository: a change that introduces a replacement deletes what it replaces in the same commit. Example in this history: the CI rewrite replaced the single `verify` job rather than adding jobs beside it.                                                                                              |
| 5.5 | Advisory lock around the migration runner | n/a    | IndexedDB upgrades are serialised by the browser.                                                                                                                                                                                                                                                                                   |

## 7. The gate's credibility is a social property

| #   | Technique                                       | Status   | How it is done here                                                                                                                                                                                                                                                                                                                      |
| --- | ----------------------------------------------- | -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 7.1 | Infrastructure-dependent suites on a schedule   | done     | Every required job is hermetic on a fresh runner: Playwright runs against a local `next start`, the link checker is offline, no job reads a live service. The Playwright report is uploaded `if: !cancelled()`. The one network dependency, Google Fonts at build time, is handled by Next's local fallback and does not fail the build. |
| 7.2 | Port and resource registry                      | deferred | Single-operator repository; the dev server uses one port and Playwright takes `PORT` from the environment. Condition that flips it: two working copies or agent sessions running servers at once.                                                                                                                                        |
| 7.3 | Environment preflight at every entry point      | n/a      | The app has no required environment variables; the only optional one has a default in code. Condition that flips it: the first required variable.                                                                                                                                                                                        |

## Explicitly not recommended (for now)

- **Blocking administrators from pushing to `main`** (`enforce_admins`). This is a single-maintainer repository and direct pushes are the normal workflow. The pre-push hook runs typecheck and the production build, which is the gate for that path. Flip it when a second maintainer joins or when the project has outside contributors regularly opening PRs.
- **A network-fetching link checker** (lychee, markdown-link-check) as a required job. External links rot, but a required check that goes red on someone else's outage trains the team to ignore red (7.1). The required `docs` job is offline. If external-link checking is wanted, add it as a scheduled workflow whose report is an artifact, never as a required check.
- **Build-time Mermaid rendering.** Needs a headless browser in CI and adds a failure mode to the build for a cosmetic gain. See ADR 0003.
- **Skipping CI on docs-only changes.** Total runtime is a few minutes; the skip logic would be the least-tested code in the gate (4.4).
- **Per-PR preview environments as a required check.** Vercel previews exist for every PR and are useful, but they depend on a third-party build and are not a gate. The hermetic `build` job is.
- **A `server-only` marker today.** No server modules exist (2.1). Adding the dependency without a module to protect would be a config without a tool (2.2).
